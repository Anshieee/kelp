02 · How a change travels

Intent becomes a spec, the spec becomes a branch named after its issue, and CI decides whether it reaches main.

  1. 1Intentowner words
  2. 2Spec + ADRin docs/
  3. 3Branchkel-N-slug
  4. 4Build + testspytest · playwright
  5. 5PR to mainterritory named
  6. 6CI gateslint · types · secrets · tests
  7. 7MergeLinear closes KEL-N
  8. 8Deploy / demothis page

A failing gate returns the branch to step 4. Merging to main is review-gated: no force push, no secrets in diffs.

Branch prefix is load-bearing. Only kel-<n>-<slug> auto-links to Linear team KEL. A neb- prefix fails silently and the issue never closes.

07 · Conventions

  • Branch — kel-<n>-<slug> off main; main stays releasable.
  • Commit — imperative subject, scope in parentheses, issue key in the body when useful.
  • PR — state the acceptance criterion exercised, commands run, and what was not verified. No force push, no secrets in diffs.
  • CI baseline — secret scan, lint, typecheck, unit tests. A demo workflow is added only after P0-5 exists.
  • Deploy — this page is static from netlify/: no build step, no secrets in the client.
